# Maintaining bilingual content

The site extends Fuwari with Astro's built-in i18n routing to provide two language entry points in one repository. The URL determines the interface language, post lists, and search. Post bodies are written separately and are not translated automatically.

| Route | Content |
| --- | --- |
| `/` | Redirects to the Chinese home page at `/zh/` |
| `/zh/`, `/en/` | Home page for each language |
| `/zh/archive/`, `/en/archive/` | Language-specific archives, categories, and tag filters |
| `/zh/about/`, `/en/about/` | About page for each language |
| `/zh/rss.xml`, `/en/rss.xml` | Separate post feeds |

Legacy `/about/` and `/archive/` routes redirect to Chinese pages. `/rss.xml` continues to provide the Chinese feed. Page redirects on static GitHub Pages are implemented through generated output.

## Writing posts

```sh
pnpm new-post zh/binary-search
pnpm new-post en/binary-search
pnpm dev
```

These commands create `src/content/posts/zh/binary-search.md` and `src/content/posts/en/binary-search.md`, both with `draft: true`. Without a language prefix, `pnpm new-post binary-search` defaults to `zh/`.

The directory determines the post language. Manually written posts can omit `lang`; when present, Chinese accepts `zh`, `zh_CN`, or `zh-CN`, while English uses `en`. A mismatch, an unsupported language directory, or a post directly in `posts/` causes a build error identifying the file.

For image-heavy posts, use `pnpm new-post en/binary-search/index`, keep images in that directory, and reference them with `![Description](./diagram.png)`. The URL is `/en/posts/binary-search/`, without `index`. See the [writing guide](WRITING.md) for fields and image paths.

Languages can publish independently: a Chinese post does not need an English translation. Drafts appear only in `pnpm dev`; they are excluded from production pages, RSS, search, and public translation links.

## Translation pairs and language switching

Posts with the same relative path are paired automatically, such as `zh/notes/example.md` and `en/notes/example.md`. When filenames differ, set the same frontmatter key in both:

```yaml
translationKey: binary-search-introduction
```

The key identifies translations without changing URLs. Two posts in the same language cannot share a key. Use a short, stable English identifier and avoid changing it after pairing.

On a post page, the language switcher opens the corresponding published translation when available; otherwise it opens the target language's home page. Home, About, and archive pages switch to their counterpart. Language-specific archive filters and pagination do not carry across languages.

Switching languages uses a full-page navigation to update menus, sidebars, the document language, and the search index together. Cross-language links in posts should also include the full language path, such as `/en/posts/binary-search/`; Chinese links use `/zh/posts/binary-search/`.

## Content and search isolation

Home pagination, archives, category and tag counts, adjacent-post navigation, and RSS read only posts in the active language directory. The same tag name can be used in both languages without combining counts.

Pagefind uses `<html lang>` (`zh-CN` or `en`) to generate separate language indexes. The browser loads the current language's index, so an identical query returns only Chinese pages from the Chinese entry point and only English pages from the English entry point. Empty-result messages use the active language. Development mode does not generate the index; verify real search with `pnpm build` and `pnpm preview`.

Each post outputs its own canonical URL. `hreflang` is emitted only for actual translations; the home-page fallback is not labeled as a post translation. Renaming a post changes its URL, and a pairing key does not create a redirect from the old URL.

## Maintenance and validation

| Path | Purpose |
| --- | --- |
| `astro.config.mjs` | Astro i18n configuration, language prefixes, and legacy redirects |
| `src/i18n/locales.ts` | Supported languages and HTML language identifiers |
| `src/i18n/translation.ts`, `src/i18n/languages/` | Fuwari interface translations |
| `src/content/spec/zh/about.md`, `src/content/spec/en/about.md` | Chinese and English About content |
| `src/utils/content-utils.ts` | Directory, language, and translation validation; language-specific content queries |
| `scripts/new-post.js` | Draft generation by language |

```sh
pnpm lint
pnpm check
pnpm test:i18n
pnpm build
pnpm preview
```

The regression test creates temporary posts and covers language isolation, pagination, translations, drafts, images in post directories, and search indexes, then removes the fixtures. The existing GitHub Actions workflow publishes changes merged into `main`.

Implementation references: [Astro internationalization](https://docs.astro.build/en/guides/internationalization/), [Astro multilingual content recipe](https://docs.astro.build/en/recipes/i18n/), and [Pagefind multilingual search](https://pagefind.app/docs/multilingual/). Fuwari's post `lang` field alone does not provide these routes and content partitions.
